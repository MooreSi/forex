## The two things that were actually broken

### 1. The stage3/020 fix never reached the main signal path

Driving its demo end-to-end showed the signal coming to rest in `pending` — the
exact state PendingWatcher re-activates every 20 seconds, for an order that may
already be live. Three separate defects, each alone enough to undo the whole
task:

- The routing was wired into `open_trade_from_signal`, but **fresh Telegram
  signals do not go through it** — they call `open_trade` directly, and that
  handler reset every failure to `pending`.
- `park_signal_unknown` was guarded on `status='activating'`; on that path the
  signal is `'active'`. So once the routing was wired, the park logged success
  and changed nothing.
- `reset_signal_to_pending` was an unguarded second door that overwrote the
  park on the way out.

**Every unit test passed throughout**, because none of them ran the caller.

connection**, so a client would have been welcomed, licensed, then dropped
before it learned what version to update to. LAN discovery was dead too.

`tools.checks all` was 8/8 through all of it. This is the fourth time this repo

## Added after this note was first written

**Four dashboard timers were reading the database on the event loop.** The
circuit-breaker badge in the header polls every 5 seconds, and that read is a
synchronous SQLite call — NiceGUI runs a sync timer callback inline, so every
tick froze every page, every websocket and every other timer for the length of
the read, on a machine also running the trading loops. If the UI has ever felt
like it "sticks", this is a candidate. Fixed by making those four callbacks
async and awaiting a version that hops off the loop.

The hygiene task claimed 33 timers had this problem. Measured: 36 timers, of
which **23 were already fine** and 9 more only touch their own labels. Four
were real. Worth saying because the planned fix was a shared helper for all 36,
which would have been a large change justified by a number that was not true.

**Every silent exception in the dashboard now says something.** 38 places
caught a failure and did nothing — a refresh could fail and leave
yesterday's numbers on screen with no log and no indicator. Eight were in the
Reversal panel alone: the balance banner, the stat cards, the levels list, the
open-signals list, the performance tables. Nothing about the behaviour changed;
they just say so now, and the gate is at zero.

**A licence bypass cannot be added quietly.** Three places store a licence key,
and all three check its signature first. That is now asserted structurally, so
the guard is against a *new* save site being added without a check — which is
the shape a bypass would actually take, rather than an existing check being
deleted.

**More tests where the risk is.** The sync handshake that stands between a
socket and `open_trade()`; the Mac-unreachable watchdog and all six conditions
that stop it crying wolf; the order of the cluster TLS handshake (the pin must
be checked *before* the shared token is sent — the isolated pinning tests never
covered that); the machine fingerprint your licences are bound to.
